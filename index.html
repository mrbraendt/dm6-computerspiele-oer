🎮 Wie entsteht ein Spiel?

Hinter jedem Spiel – von Minecraft bis Brawl Stars – stecken dieselben Grundbausteine: eine Figur, Regeln, ein Ziel und ein Programm, das alles 60-mal pro Sekunde neu berechnet. In dieser Einheit nimmst du ein kleines Spiel auseinander, veränderst es selbst und entwirfst danach dein eigenes.

📚 So läuft die Einheit

  • 🧱 Schritt 2–3: Was ein Spiel ausmacht und wie ein Computer es berechnet
  • 🔧 Schritt 4–7 – Werkstatt: Du veränderst ein echtes Spiel mit Reglern und findest heraus, was im Code passiert
  • 🧲 Schritt 8: Mit welchen Tricks Spiele dich festhalten – und was davon fair ist
  • 🎤 Schritt 9–10: Du baust in Keynote die Präsentation deines eigenen Spiels und stellst sie vor (wird benotet)

👥 Arbeitsformen: In der Werkstatt arbeitest du allein, vergleichst aber in Schritt 7 mit einem Partner. In Schritt 9 prüft ein Partner deine Folien, bevor du präsentierst. Dein Fortschritt wird auf diesem iPad gespeichert.

🎮 Was macht ein Computerspiel aus?

🧱 Die fünf Grundbausteine

  1. 🦸 Spielfigur: das, was du steuerst
  2. 🏁 Ziel: Was willst du erreichen? (Punkte sammeln, ein Level schaffen, überleben …)
  3. 📜 Regeln: Was darfst du? Was passiert, wenn …?
  4. 🎨 Grafik: alles, was du auf dem Bildschirm siehst
  5. 👆 Interaktion: Du kannst etwas tun – Tasten drücken, tippen, wischen

🔎 Kurz testen

💻 Wie berechnet der Computer ein Spiel?

Ein Spiel ist ein Programm, das immer wieder von vorn durchläuft – wie ein Daumenkino. Jedes einzelne Bild heißt Frame. In jedem Frame passiert:

  1. Der Computer prüft, was du gerade tust (Taste, Touch).
  2. Er berechnet, was sich bewegt hat und ob sich etwas berührt.
  3. Er zeichnet alles neu.
  4. Und wieder von vorn – meist 60-mal pro Sekunde.

🎯 Unser Spielprojekt: ein Sammelspiel

Als Beispiel nehmen wir ein einfaches Sammelspiel: Du steuerst eine Figur, sammelst Sterne und bekommst Punkte. In den nächsten vier Schritten baust du es Stück für Stück auf – und veränderst es mit Reglern selbst.

Die leere Spielfläche – noch passiert nichts.

🛠️ Canvas und Koordinaten

Die Spielfläche heißt Canvas (Leinwand). Sie ist 600 Pixel breit und 400 Pixel hoch. Jeder Punkt hat zwei Zahlen: x (wie weit nach rechts) und y (wie weit nach unten). Achtung: Gezählt wird von oben links – dort ist x = 0 und y = 0.

💡 Code und Anweisungs-Blöcke

Computer verstehen kein Deutsch, sondern eine genaue Programmiersprache – für Webspiele meist JavaScript. Wir zeigen dir jeden Schritt als Anweisungs-Blöcke (wie bei Scratch). Wer will, kann unter „Profi-Tipp“ den echten Code ansehen.

👤 Schritt 4: Die Spielfigur

Eine Spielfigur ist für den Computer zunächst nur eine Form mit Farbe, Position und Größe. Diese Werte merkt er sich in Variablen – Speicherplätzen, deren Inhalt sich ändern kann.

🧩 Anweisungen an den Computer – sie ändern sich mit deinen Reglern
🟢
BEI SPIELSTART
🎨
ZEICHNE ein Rechteck Farbe: Grün Position: x = 275, y = 175 (von oben links gemessen) Größe: 50 × 50 Pixel
Profi-Tipp: So sieht echter JavaScript-Code aus
// Spieler zeichnen zeichenfläche.fillStyle = '#4CAF50'; zeichenfläche.fillRect(275, 175, 50, 50);

🎯 Deine Mission

🏃 Schritt 5: Bewegung

Bewegung heißt für den Computer: In jedem Frame wird die Variable spielerX oder spielerY ein bisschen größer oder kleiner – je nachdem, welche Taste gedrückt ist.

🧩 Anweisungen an den Computer
🔄
IN JEDEM FRAME
⌨️
WENN Pfeiltaste → gedrückt
➡️
spielerX = spielerX + 5
⌨️
WENN Pfeiltaste ← gedrückt
⬅️
spielerX = spielerX − 5
🧱
FALLS spielerX größer als der Rand → zurück an den Rand (genauso für links, oben und unten)
Profi-Tipp: So sieht echter JavaScript-Code aus
if (tasten['ArrowRight']) { spielerX = spielerX + 5; } if (tasten['ArrowLeft']) { spielerX = spielerX - 5; } // Rand: nicht weiter als 600 - Größe if (spielerX > 550) spielerX = 550;

⭐ Schritt 6: Sammeln und Berühren

Woher weiß der Computer, dass die Figur den Stern berührt? Er berechnet in jedem Frame den Abstand zwischen beiden. Ist er kleiner als ein festgelegter Wert, zählt das als Berührung – eine Kollision.

🧩 Anweisungen an den Computer
⭐
MERKE DIR: der Stern Position x, y · gesammelt? → nein
🔄
IN JEDEM FRAME
💥
FALLS Abstand Figur–Stern kleiner als 40 Pixel
✅
Stern gesammelt Stern erscheint an einer neuen, zufälligen Stelle
Profi-Tipp: So sieht echter JavaScript-Code aus
const abstand = Math.sqrt(dx * dx + dy * dy); // Satz des Pythagoras if (abstand < 40) { stern.gesammelt = true; }

🏆 Schritt 7: Punkte, Zeit und Hindernisse

Erst mit Regeln wird aus Herumlaufen ein Spiel: Punkte für Sterne, eine Zeitgrenze, ein Hindernis, das Punkte kostet. Jede Regel ist für den Computer ein WENN … DANN ….

🧩 Anweisungen an den Computer
🟠
MERKE DIR: punkte = 0 · zeit = 30 Sekunden
🔄
IN JEDEM FRAME
⭐
WENN Stern gesammelt → punkte = punkte + 10
🟥
WENN Hindernis berührt → punkte = punkte − 20
⏱️
WENN zeit = 0 → Spiel vorbei, Punkte anzeigen
Profi-Tipp: So sieht echter JavaScript-Code aus
if (stern.gesammelt) { punkte = punkte + 10; } if (berührt(spieler, hindernis)) { punkte = punkte - 20; } if (zeit <= 0) { spielVorbei(); }

🧲 Schritt 8: Warum Spiele dich festhalten

Spielefirmen wollen, dass du lange spielst – und manchmal, dass du Geld ausgibst. Dafür nutzen sie bestimmte Spielmechaniken. Manche machen einfach Spaß, andere setzen dich unter Druck.

🏅 Belohnung
Punkte, Sound, Glitzer – dein Gehirn freut sich über jede Belohnung.
📈 Fortschritt
Ein Balken, der fast voll ist. Nur noch ein Level …
🗂️ Sammeln
Ein Album, in dem nur noch eine Karte fehlt.
🎲 Zufall
Truhen und Lootboxen – vielleicht ist diesmal etwas Seltenes drin.
📅 Tägliche Serie
„Komm morgen wieder, sonst ist deine 12-Tage-Serie weg!“
👥 Vergleich
Ranglisten und Freunde, die schon weiter sind.
💰 Kaufanreize
Timer, Rabatte, Spielwährung – kennst du aus „In-App-Käufe“.

🔎 Welche Mechanik steckt dahinter?

⚖️ Fair oder unfair?

Eine Mechanik ist eher fair, wenn sie das Spielen schöner macht und du jederzeit aufhören kannst. Sie ist eher unfair, wenn sie dich unter Druck setzt (Angst, etwas zu verpassen), mit Zufall um Geld spielt oder Spieler, die zahlen, gewinnen lässt.

Das brauchst du gleich für Folie 7 deiner Präsentation.

🎤 Schritt 10: Präsentieren

Du stellst dein Spiel in 3 bis 5 Minuten vor. Danach dürfen die anderen Fragen stellen. Bewertet wird nicht nur, was in deinem Spiel vorkommt, sondern vor allem, ob du erklären kannst, warum du es so entworfen hast.

Bereich🌟 Sehr gut👍 Gut / in Ordnung🔧 Noch nicht
💡 Spielidee & RegelnZiel, Figur und Regeln sind klar; mindestens 3 Regeln als WENN … DANN …Idee verständlich, Regeln teilweise unklarMan versteht nicht, wie das Spiel funktioniert
🧠 Entscheidungen begründenErklärt mehrere Entscheidungen mit „weil …“ und nennt eine verworfene IdeeBegründet einzelne EntscheidungenNur Beschreibung ohne Begründung
⚖️ Fesselnd, aber fairNennt die Mechaniken seines Spiels und beurteilt, ob sie fair sindNennt Mechaniken ohne BewertungFehlt
🖼️ FolienGut lesbar, wenig Text, eigene Skizzen oder BilderLesbar, aber viel TextSchwer lesbar oder unvollständig
🎤 VortragFrei gesprochen, Blickkontakt, beantwortet Fragen sicherTeilweise abgelesenNur abgelesen

💡 Tipps für den Vortrag

  • 👀 Sprich zu den Zuhörern, nicht zum Bildschirm.
  • 📝 Auf der Folie stehen Stichworte – den Rest erzählst du.
  • ⏱️ Übe einmal laut mit Partner und stoppt die Zeit.
  • ❓ Überlege vorher: Welche Frage könnte kommen? Was antwortest du?

🙋 Als Zuhörer: Stelle nach jedem Vortrag mindestens eine echte Frage, z. B. „Warum hast du dich für … entschieden?“ oder „Was passiert, wenn …?“
